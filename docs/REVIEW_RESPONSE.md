## New unverified items introduced by these fixes (honest list)
- `RawAirData` CRC byte order (little-endian first) follows libcanard behaviour; the spec text only states little-endian signature and "CRC prepended". Verify with the DroneCAN GUI Tool.
- FDCAN `HAL_FDCAN_Stop/Start` as the bus-off recovery sequence, `ProtocolStatus.BusOff`, `RCC_FLAG_PORRST`: written from memory of the H7 HAL, compiled only against a stub.
- `ADB_CAN_TX_FIFO_DEPTH` must match the CubeMX setting.

## Things the review did not mention but the same analysis surfaced
- The previous test suite could not detect a driver that misreads a register's *enable* semantics, because the simulators mirrored the same assumption. Simulators now model gating for the BMP581 drdy; the hardware test plan keeps register-level checks (test B3/B4).
